# Re-measurement plan, 2026-11-24

The recorded run of 2026-11-23 was made before three things changed:

1. the cloud model is measured with `gemini-4-hydrogen`,
2. an item whose line says the observer could not tell is no longer sent to the
   cloud at all, and
3. an accepted cloud answer can now become the finding the rule pack judges, so a
   cloud answer can settle an item at pass or fail instead of only adding a
   clause and a remedy.

This plan runs the forty observations again, plus the ten notes written for the
cloud path, so the tables match the shipped code and so the spread of one arm
against itself is a measured number instead of an assumption.

Run it after 17:00 KST (08:00 UTC), when the free daily quota for
`gemini-4-hydrogen` resets. Nothing here needs to be done before the code is
deployed: the runner opens the published page.

## What the run has to answer

1. How many cloud calls the shipped code makes on the forty notes, and how many
   of those the gate accepts. Expected: only items with a decisive line, so the
   number is well under twenty.
2. How many of the ten cloud path notes the on-device path leaves open, and how
   many of those the hybrid settles, with how many of them agreeing with the human
   key. This is the number the previous run could not give, because nothing in
   that run was built for the cloud to settle.
3. Whether the gate keeps an over-claim out of the record on the two control
   notes (O09, O10), where a person wrote review and a confident cloud answer
   would say fail.
4. How far the on-device model moves between two runs of the same forty notes in
   the same session. That is the number that decides whether 36 and 38 are
   different at all.

## Before the session

1. Deploy the current `main` to `gh-pages` and open the live bench page once.
   The run measures the published build, not a local copy.
2. Build the config fragment from `.env.local` on a machine that has the file.
   The value is pasted into the notebook and never written into the repository.

```bash
cd build/walkproof
python3 - <<'PY'
import base64, json
vals = {}
for line in open(".env.local"):
    line = line.strip()
    if line and not line.startswith("#") and "=" in line:
        name, value = line.split("=", 1)
        vals[name] = value
keys = ["VITE_FIREBASE_API_KEY", "VITE_FIREBASE_AUTH_DOMAIN", "VITE_FIREBASE_PROJECT_ID",
        "VITE_FIREBASE_STORAGE_BUCKET", "VITE_FIREBASE_MESSAGING_SENDER_ID", "VITE_FIREBASE_APP_ID"]
cfg = {key.replace("VITE_FIREBASE_", "").lower().replace("_", ""): vals[key] for key in keys}
print(base64.urlsafe_b64encode(json.dumps(cfg).encode()).decode().rstrip("="))
PY
```

The keys become `apikey`, `authdomain`, `projectid`, `storagebucket`,
`messagingsenderid` and `appid`, which is the shape `src/config/firebase.ts`
reads.

## The session

Kaggle, new notebook, accelerator none, internet on. One cell:

```python
BASE = "https://luke-shin-ai.github.io/walkproof/bench/"
CFG = "<the fragment from the step above>"
MODEL = "gemini-4-hydrogen"
CLOUD_ONLY = 0        # the six item baseline is kept from 2026-11-23
HOLDOUT = 1           # the ten notes kept apart from the forty go through the device
OPEN = 1              # the ten cloud path notes go through both arms
REPEAT = 1            # the same forty item arms a second time, for the spread
TAG = "-d6"

exec(open("/kaggle/working/kaggle_runner.py").read())
```

Paste `bench/kaggle_runner.py` into `/kaggle/working/kaggle_runner.py` first.
The run takes about twenty minutes of model time per pass, so roughly forty with
`REPEAT = 1`, plus ten cloud calls for the cloud path set.

Keep `CLOUD_ONLY` at 0 when `OPEN` is 1. The ten cloud path calls and the calls
the forty item arms make share one daily meter of 20, and a run that starts with a
spent meter measures the meter, not the product.

## What to read out of the session

| line | what it gives |
|---|---|
| `METRICS_BEGIN` to `METRICS_END` | one JSON line per arm: `agreement`, `cloudCalls`, `refused`, `settledByCloud`, `settledByCloudCorrect`, `verdicts` |
| `ITEM {... "arm": "open-device" ...}` | each cloud path note as the device alone records it |
| `ITEM {... "arm": "open-hybrid" ...}` | the same note after the cloud answer, with `gate` and `cloud` |
| `VARIATION device n of 40 [...]` | how many of the forty the device arm answered differently in its second pass |
| `VARIATION hybrid n of 40 [...]` | the same for the hybrid arm |
| `ITEM ...` lines for `device` and `hybrid` | per item `expected`, `recorded`, `check` and `gate` |
| `B64:` lines | the whole result file, gzipped and base64 encoded |
| `/kaggle/working/walkproof-bench-result-d6.json` | the same file, written in the session |

## If the quota is not back

- A 404 or "model not found" for `gemini-4-hydrogen` means the model name is not
  offered to this project. Run with `MODEL = "gemini-3.5-flash-lite"` and record
  the model in the table exactly as the run reports it.
- A `429` on the first call means the quota has not reset. Stop the session and
  try the next morning; a run that starts with a spent quota measures the quota,
  not the product.

## What not to do

- Do not put the config fragment, the API key or the App Check debug token in any
  file under version control. `npm run check:ai-tells` and
  `npm run check:pages` both fail on them, and the repository is public.
- Do not delete the 2026-11-23 run. It is the only measurement of the hybrid
  before the strong hybrid, and the README cites it by name.
